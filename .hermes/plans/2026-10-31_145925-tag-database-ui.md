# Tag Database UI Implementation Plan

> **For Hermes:** use subagent-driven-development to execute task-by-task, or work top to bottom directly. Tasks are ordered so each one is independently verifiable and committable.

**Goal:** turn `/docs/tag-database` from a big table into the definitive place to look up any tag, where every queued query form resolves, every value shows all its readings together, and every tag is a linkable URL.

**Architecture:** keep the existing shape. `scripts/parse-*.py` produce per-namespace JSON in `/tmp`, `scripts/build-tag-db.py` merges to `data/tag-db.json` and renders `docs/tag-database.md` plus `ai/tag-database.md`. All UI work is in that one generator, so the pages stay generated and never hand-edited.

**Tech stack:** Python 3 stdlib only, Jekyll, vanilla JS in the generated page. No new dependencies.

**Repo:** `/home/agent/repos/esim-knowledge` (public, serves euicc.tech).
**Data source:** `/home/agent/gsma-specs` (never committed).

# Phase P0: correctness

## Task 1: Normalise the query

**Objective:** every documented query form resolves.

**Files:** Modify `scripts/build-tag-db.py` (the `JS` constant and `render_human`).

**Step 1:** emit a normalised search key plus the ASN.1 tag number on every row.

In `render_human`, per row add `data-n` when the tag is high-tag-number form:

```python
tagnum = str(int(r["tag"][2:4], 16)) if r["tag"][:2] in ("BF", "9F", "5F", "7F") else ""
```
Add to the `<tr>`: `data-n="{tagnum}"`.

**Step 2:** add a normaliser used by both the filter and the query.

```js
function norm(s){
  return s.toLowerCase()
          .replace(/[\s'"]/g, '')      // "bf 36", "Tag 'BF36'", "bf36"
          .replace(/^tag/, '')          // "tag bf36"
          .replace(/^0x/, '');
}
```
Store `data-q="{norm(search)}"` on each row instead of `data-s`.

**Step 3:** bracket form. In `update()`, before matching:

```js
var m = q.match(/^\[(\d+)\]$/);
if (m) { match on row.dataset.n === m[1]; }
```

**Verify (live, after deploy):**
- `bf 36` → 3 or more rows, first `BF36`
- `Tag 'BF36'` → same set
- `[54]` → the BF36 rows
- `[0]`-style misses fall back to substring matching, never to a blank page

**Commit:** `fix(tag-db): normalise spaced, quoted and bracketed tag queries`

## Task 2: Group by tag value and rank exact hits first

**Objective:** `83` reads as one object with 23 readings, not 23 unrelated rows.

**Files:** `scripts/build-tag-db.py` (`render_human`, `CSS`).

**Step 1:** sort rows by `(ns order, tag, spec)` before rendering, then emit one `<tbody>` per `(ns, tag)` group:

```python
from itertools import groupby
key = lambda r: (ORDER.index(r["ns"]), r["tag"])
for (ns, tag), grp in groupby(sorted(rows, key=key), key=key):
    g = list(grp)
    L.append(f'<tbody class="grp" id="tag-{ns}-{tag}" data-tag="{tag}">')
    for i, r in enumerate(g):
        cells = f'<td rowspan="{len(g)}" class="tagcell"><code>{tag}</code></td>' if i == 0 else ""
        ...
```
Keep the visible tag cell identical to today, but now it spans the group.

**Step 2:** add a meaning count on the first row of a group with more than one row: a small `.badge` after the tag, e.g. `9 readings`.

**Step 3:** ranking. In `update()`, when the query is pure hex, order visible groups so exact tag matches come first:

```js
rows.sort(byExactTagThenName)  // compare dataset.tag === q, then startsWith
```
Re-append in that order to the tbody container so the DOM order changes, not just visibility.

**Verify:**
- `83` → first group is tag `83`, badge shows the number of readings, the GlobalPlatform and allocator readings are inside the same group block
- `E0` → first group is `E0`, not a name containing "e0"
- default (no query) order unchanged: namespace then tag

**Commit:** `feat(tag-db): group rows by tag value, rank exact tag hits first`

**Step 2:** on load, honour the hash:

```js
function fromHash(){
  var h = decodeURIComponent(location.hash.replace(/^#/, ''));
  var m = h.match(/^tag-([a-z]+)-([0-9A-F]+)$/i);
  if (!m) return;
  input.value = m[2];
  active = m[1];
  update();
  var el = document.getElementById('tag-' + m[1] + '-' + m[2]);
  if (el) el.scrollIntoView({block:'center'});
  if (el) el.classList.add('flash');
}
window.addEventListener('hashchange', fromHash);
```

## Task 4: Stop mislabelling the RSP namespace

**Objective:** no row claims to be eSIM RSP when it came from a USIM or GlobalPlatform document.

**Files:** `scripts/build-tag-db.py` (`build_rows`, `NS_META`, `ORDER`).

**Step 1:** classify by source document instead of by which parser produced the row:

```python
def rsp_bucket(spec):          # spec here is the pre-label name
    if spec.startswith(("SGP.", "TCA-")):
        return "rsp"
    if spec.startswith(("3110", "3111", "3115", "3116", "3113", "23003")) or \
       spec.startswith("ETSI-TS-102") or spec.startswith("ETSI-TS-131"):
        return "card"
    if spec.startswith(("GPC", "GPD")):
        return "gp"
    return "card"
```

**Step 2:** add namespace `card` to `NS_META` and `ORDER`:

```python
"card": {
    "label": "3GPP / ETSI card-layer tags",
    "key": "(document, clause, tag)",
    "blurb": "Tags read out of USIM file contents and UICC command clauses. "
             "Not RSP messages. Named only where the source document names them.",
},
```
Place it after `gp` in `ORDER`.

**Step 3:** drop rows whose name is a prose fragment. Reject a name that ends in a preposition or conjunction, or that has no capitalised word:

```python
BAD_TAIL = re.compile(r"\b(with|of|for|and|or|the|to|in|on|by|from|that)$", re.I)
if BAD_TAIL.search(name) or not re.search(r"[A-Z]", name):
    skip
```
This removes `82 -> "BER-TLV object returned with"` and `8A -> "discovery signalling for solicitation"`.

**Verify:** `grep -c 'eSIM RSP ASN.1' docs/tag-database.md` equals the SGP/TCA row count only. `grep 'MMS Implementation' docs/tag-database.md` no longer shows the RSP label. Row total drops slightly and is reported as such.

**Commit:** `fix(tag-db): classify rows by source document, not by parser`

## Risks

- **Grouping changes row semantics.** Rowspan plus sorting can look like the page lost rows. The badge count and the unchanged row total in the header cover this.
- **The `card` split lowers the headline number.** 1,307 becomes roughly 1,265 with a visible sixth namespace. Report both numbers rather than hiding the reclassification.
- **Hash routing fights the sticky toolbar.** `scroll-margin-top` must be at least the toolbar height.
- **Task 4 depends on the pre-label spec name.** `spec_label()` runs at render time today; the classification must read the raw name before labelling or TCA rows will fall into `card`.

## Out of scope

Per-tag static pages for SEO (one page per tag), server-side search, and virtualised rendering. All three become worthwhile past about 5,000 rows; not now.
